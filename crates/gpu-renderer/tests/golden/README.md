# Scene GPU golden regressions

Run from the repository root:

```sh
LIBGL_ALWAYS_SOFTWARE=1 cargo test -p gpu-renderer --test scene_golden -- --ignored --test-threads=1 --nocapture
```

The five GPU tests are explicitly ignored in the ordinary workspace suite because each
requires EGL 1.5, `EGL_MESA_platform_surfaceless`, GLES 2 and an installed software
renderer. Explicit runs fail on missing GPU support; they never silently skip.
No desktop display or visible surface is used. The comparison gate itself runs
in ordinary tests. Keep GPU cases on one thread so EGL display teardown is safe.

The ten original PNG references cover parent transforms, radians/rotation, layer
order, opaque/translucent/additive blending, output cover/resize, padded TEX UVs
and orientation, opacity and camera-zoom timelines, TEXS1/2/3 sprite frames/loops,
basic parallax axes/pause, and real embedded TEXB0004 video decoding/uploads.
Sprite fixtures use image indices and six-component frame bases established by
[local native analysis](../../../../docs/reverse-engineering/wallpaper-engine-textures.md).
Video checks also change RGBA storage size and recreate the EGL context while
retaining CPU frames, exercising the output-replacement upload contract.

References are original synthetic fixtures generated independently by
`generate_references.py` from documented geometry, source-over/additive arithmetic
and explicit texture pixels. The test reads committed packages and ordered inputs
from the [behavior matrix](../../../../tests/fixtures/scene-behavior/README.md),
calls the production `SceneGpuRenderer`, then reads actual RGBA pixels. The
ordinary suite verifies all 13 project/package identities, PNG hashes and parser
outcomes. Eight baseline packages retain these same twenty comparisons. Five
atlas packages add thirty comparisons for image selection, rotation, flips,
skew, frame boundaries, fixed-time pause, loop and context replacement. Their
legacy single-image adapter rejection is still checked independently.
Seven additional PNGs are generated by `generate_atlas_references.py` using
explicit coordinate permutations and bilinear interpolation of four authored
colors. The original ten PNGs are unchanged. A separate GPU case adds five
comparisons for upload rollback/retry, image limits, clear/reload and affine
effect composition, for 55 comparisons total. References
are never regenerated from renderer output. Update them deliberately with:

```sh
python3 crates/gpu-renderer/tests/golden/generate_references.py
# Read-only A1 check; add --write only for a deliberate analytical update.
python3 crates/gpu-renderer/tests/golden/generate_atlas_references.py
```

A third GPU case adds two exact analytical byte assertions without PNG files.
It replaces the multi-image sample's texture with a 5×5 opaque black image whose
center is RGB (250, 150, 100). Reduction to 1×1 must yield (10, 6, 4, 255), from
the center's 1/25 coverage. Adding an authored solid 2×2 mip must instead yield
its color (80, 40, 20, 255), proving that only missing levels are synthesized.
This covers our area-weighted mip convention, not native-engine filtering parity.

Two additional GPU cases in `support/atlas_sampling.rs` use analytical solid-color
expectations. They check packed-frame isolation at 32/8/4/1 pixels, rotated and
flipped crops, independent authored mip chains, full-image/crop transitions,
looping, clear/reload and context replacement. An ordinary test checks mip-chain
preservation and full-image classification, including rejection of a skewed crop.
These probes cover the conservative base-level crop filter; arbitrary skewed
edges and native minification parity remain outside their claims.

The gate requires all of:

- SSIM >= 0.995, averaged over overlapping 8x8 luminance box windows, stride 4.
- Mean squared error <= 1.0 across every RGBA byte.
- Maximum absolute channel error <= 2 on the 0–255 scale.

The [SSIM formula](https://ece.uwaterloo.ca/~z70wang/publications/ssim.pdf) uses
`C1=(0.01*255)^2`, `C2=(0.03*255)^2`. This fixture metric uses uniform local windows
and population variance, not the paper's Gaussian implementation. RGBA error
gates additionally catch alpha and channel errors that luminance SSIM can miss.
Failure writes actual and amplified RGB difference PNGs under
`target/scene-golden-failures/`, and reports the metrics/path in the assertion.

On the A1 llvmpipe run the original twenty comparisons retained SSIM 1.0 and zero
error. All 55 passed: minimum SSIM 0.9990804, maximum MSE 0.171875 and maximum
channel error 1. See the [A1 record](../../../../docs/validation/a1-atlas-rendering.md).
These fixtures establish deterministic regression
coverage. They do not establish Wallpaper Engine screenshot parity, real niri
pointer/hotplug behavior, vendor GPU coverage, or the eight-hour L2 soak criterion.
